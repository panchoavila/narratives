# Narratives as a fork of Revyme

How this repository relates to [Revyme](https://github.com/revyme-web/builder), what it changes,
and how to keep it mergeable in both directions.

## Repositories

```
revyme-web/builder          upstream Revyme (public, AGPL-3.0)
  └─ narratives             this repository (public): the platform
       └─ private workspace  sites, content, research and deploy config built on Narratives
```

- **Shared history.** Upstream commits are kept byte for byte. `git merge-base main upstream/main`
  is a real upstream commit, so upstream changes merge in with `git merge` and contributions go
  back as ordinary pull requests.
- **Private content stays out.** Sites, client content, research evidence and deployment config
  never enter this repository. A private workspace adds them on top, as one more fork layer.

## Branches

| Branch | What it holds |
|---|---|
| `main` | Narratives. Every commit passes the gates in [CONTRIBUTING.md](./CONTRIBUTING.md). |
| `upstream-main` | A mirror of `revyme-web/builder:main`, fast-forward only, never committed to. |
| `contrib/<topic>` | A change offered upstream. Cut from `upstream-main`, with no Narratives branding. |

### Syncing with upstream

```bash
git fetch upstream
git switch upstream-main && git merge --ff-only upstream/main && git push origin upstream-main
git switch main && git merge upstream-main      # resolve, then run every gate before pushing
```

### Offering a change upstream

1. Cut `contrib/<topic>` from `upstream-main`.
2. Cherry-pick or re-apply the change without Narratives names or assets.
3. Run upstream's gates and open the pull request against `revyme-web/builder`.

Keep each contribution small and self-contained. Upstream's CONTRIBUTING lists what review checks.

## Naming policy

"Revyme", its logo and revyme.com / revyme.app are trademarks (see NOTICE, "Trademarks").

**What Narratives renames.** The product identity:
- the window title, the editor mark and favicons, and the welcome screen;
- the "About" notice;
- how the editor and its AI agent refer to themselves;
- exported READMEs and "Made with" texts.

**What keeps the Revyme name.** Anything that describes origin, an upstream service, or a
compatibility identifier existing projects depend on. Renaming these would break user projects
and upstream mergeability:
- the `@revyme/runtime` import specifier, `Revyme*` component names and `data-revyme-*` attributes;
- the `_revyme/` project folder and `revyme-v1` project format;
- the `@generated by Revyme` / `AUTO-GENERATED by Revyme` markers that the code detects;
- Revyme Cloud features, credits and the "Made in Revyme" badge, which are upstream services;
- the "Revyme plugin format", the dialect the oracle and the AI agent describe, and code comments.

## License obligations checklist

- [ ] LICENSE and NOTICE are unmodified, and the source files keep their copyright notices and
      author attributions (NOTICE §7(b)).
- [ ] [CHANGES.md](./CHANGES.md) records the modifications and their dates (AGPL §5(a)).
- [ ] The editor shows the Appropriate Legal Notices: Logo menu → "About Narratives", which gives
      copyright, the absence of warranty, the license, the NOTICE terms and the source.
- [ ] Every network deployment links its users to the exact source it runs (AGPL §13).
      "About Narratives" links to `VITE_SOURCE_URL`, defaulting to this repository, at the commit
      the build was made from. A downstream layer that adds private files sets
      `VITE_SOURCE_COMMIT` to the public Narratives commit its platform code equals, and
      deploys only when that equality holds. Deploy only platform code that is pushed and public.
- [ ] Third-party code shipped in the runtime keeps its license file:
      `packages/revyme-runtime-scene/{THREE,HYPHEN,QR-CODE,RICH-CONTENT}-LICENSE*` and
      `src/vendor/qrcode.LICENSE`.
